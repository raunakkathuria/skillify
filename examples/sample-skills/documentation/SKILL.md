# Technical Documentation

Guidelines for writing effective technical documentation.

## Document Types

1. **README** — Project overview, quickstart, setup
2. **API Reference** — Endpoint docs, request/response examples
3. **Architecture Decision Records (ADRs)** — Why decisions were made
4. **Runbooks** — Operational procedures for incidents
5. **Tutorials** — Step-by-step guides for common tasks

## Writing Principles

- Write for the reader's context level
- Use concrete examples over abstract explanations
- Keep paragraphs short (3-4 sentences max)
- Use headers for scanability
- Include code samples that actually work
- Update docs when code changes (treat as part of the PR)

## Tools

- Markdown for source-controlled docs
- OpenAPI/Swagger for API specs
- Mermaid for diagrams
- Documentation sites: Docusaurus, MkDocs, GitBook
